# GymFlow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Construir o CRM de ginásio GymFlow: inscrições com ativação por email, planos/assinaturas/pagamentos manuais, controlo de portaria por QR e dashboard.

**Architecture:** App Laravel monolítica com Blade. As regras de negócio vivem em poucas classes de serviço (`SubscriptionService`, `ClientEnrollmentService`, `AccessService`, `DashboardStats`) e em métodos dos modelos. Os controllers são finos e a validação é feita em Form Requests. O estado da assinatura é calculado a partir das datas, e um comando diário termina as assinaturas com mais de 2 dias em atraso.

**Tech Stack:** Laravel 13 / PHP 8.4, Blade + Tailwind 4 + Vite, MySQL (dev) / SQLite em memória (testes), PHPUnit 12, `bacon/bacon-qr-code`, `html5-qrcode`.

**Spec:** `docs/superpowers/specs/2026-11-04-gymflow-design.md`. Ler antes de qualquer tarefa; em caso de dúvida, o spec manda.

## Global Constraints

- Ler `.ai/rules/index.md` e as regras aplicáveis antes de editar (CLAUDE.md do projeto). Criar ficheiros com `php artisan make:* --no-interaction`.
- Código, tabelas e identificadores em inglês; **toda a interface em português de Portugal**. O conceito chama-se `Client` no código e "Aluno"/"Alunos" na interface.
- Timezone `Europe/Lisbon` (`config/app.php`), locale `pt_PT`.
- Nunca apagar registos de alunos, assinaturas, pagamentos ou acessos: só desativar ou terminar. Sem rotas `destroy` para estes recursos.
- Dependências novas permitidas: só `bacon/bacon-qr-code` (Composer) e `html5-qrcode` (npm). Gráficos só com HTML/Tailwind.
- Os testes correm em SQLite `:memory:` (phpunit.xml). Nada de SQL específico de MySQL; agregações por hora/dia da semana fazem-se em PHP.
- Datas e horas nos testes controladas com `$this->travelTo(...)`.
- Seguir o estilo do Laravel 13 já presente (atributos `#[Fillable]`/`#[Hidden]` nos modelos, `casts()` como método). Correr `vendor/bin/pint --dirty --format agent` antes de cada commit.
- Valores do spec: link de ativação expira em **48 h (2880 min)**; terminação automática com **mais de 2 dias** em atraso; leitura duplicada ignorada durante **60 s**; periodicidades do seeder Mensal 1/0%, Trimestral 3/5%, Semestral 6/7%, Anual 12/10%.
- Formulários POST desativam o botão de submissão ao submeter (`onsubmit`), para evitar pagamentos duplicados por duplo clique.

## Review Focus

1. **Início no fim do mês** (ex.: 31/01 mensal): o vencimento tem de ser 28/02 (ou 29/02) e depois 31/03, sem deslizar. Usar `addMonthsNoOverflow` sempre a partir de `starts_on`. Teste na Tarefa 4.
2. **Preço do plano alterado depois de haver assinaturas**: o valor das assinaturas existentes não muda. Teste na Tarefa 4.
3. **Email ou NIF repetidos na inscrição**, incluindo o email de um funcionário: erro de validação em português, sem nada criado. Teste na Tarefa 7.
4. **Pagamento numa assinatura Terminada ou cancelada**: tem de ser recusado. Teste na Tarefa 4.
5. **Funcionário ou aluno desativado com sessão aberta**: o próximo pedido termina a sessão. Teste na Tarefa 2.

**Interfaces — Produces:**
- `Subscription::status(?CarbonInterface $today = null): SubscriptionStatus`, com `$today` por omissão `today()`:
  - `ended_on !== null` → `Ended`;
  - `paid_until === null` → `Pending`;
  - `$today <= paid_until` → `Active`;
  - caso contrário → `Overdue` (mesmo com mais de 2 dias, até o comando da Tarefa 6 a terminar).
- `Subscription::amountPerPeriod(): float` = `round(monthly_price * billingPeriod.months * (1 - discount_percent/100), 2)`, com os valores copiados para a assinatura e **não** os do plano.
- `Subscription::hasOutstandingDebt(): bool` = `end_reason === EndReason::Overdue && debt_settled_at === null`.
- `SubscriptionService::recordPayment(Subscription $subscription, User $recordedBy): Payment`
  - lança `SubscriptionNotAllowedException` se `status() === Ended`;
  - 1.º pagamento (Pending): `starts_on = today()`, `period_start = today()`;
  - pagamentos seguintes: `period_start = paid_until`;
  - sempre `period_end = starts_on->addMonthsNoOverflow(months × nº de pagamentos de período, incluindo este)`, `paid_until = period_end`, `amount = amountPerPeriod()`, `type = Period`, `paid_at = now()`.
- `SubscriptionService::settleDebt(Subscription $subscription, User $recordedBy): Payment`: só se `hasOutstandingDebt()` (caso contrário lança a exceção). Cria um pagamento `type Debt` com `amountPerPeriod()` e `period_*` nulos, e marca `debt_settled_at = now()`.
- `SubscriptionService::cancel(Subscription $subscription): void`: só se o estado for `Pending` (caso contrário lança). Marca `ended_on = today()` e `end_reason = Cancelled`.
- `SubscriptionNotAllowedException`: a mensagem em pt-PT é a que se mostra ao utilizador.

    1. token inexistente ou cliente inativo → `Refused/Unknown`;

  - `POST /crm/scan` `crm.scan.store` com `{token}` → JSON `{type: string, type_label: string, reason: ?string, reason_label: ?string, client_name: ?string, scanned_at: string}`.
